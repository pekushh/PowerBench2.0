# PowerBench

> Детерминированный бенчмарк схем управления электропитанием Windows для игровых рабочих нагрузок.

PowerBench измеряет и сравнивает схемы питания (Balanced, High Performance, Ultimate Performance, пользовательские) под нагрузкой, имитирующей CPU-зависимую соревновательную игру. Результаты детерминированы — повторные запуски дают идентичные контрольные суммы.

## Особенности

- **Детерминированное ядро (GamingCpuV1)** — никакого недетерминизма: фиксированный seed, пул воркеров, контрольные суммы каждого тика
- **Автоматическое восстановление схемы** — при прерывании теста исходная схема питания восстанавливается автоматически
- **Контрольные точки** — сессия может быть продолжена после прерывания (`resume`)
- **Статистический анализ** — bootstrap (8192 итерации), доверительные интервалы, уровни доказательности (Confirmed/Probable/Preliminary)
- **Мониторинг фона** — корреляция скачков латентности с процессами системы
- **Два интерфейса** — CLI (`powerbench-cli`) и GUI (Tauri, `powerbench-app`)
- **История и отчёты** — сохранение результатов, HTML-отчёты, экспорт в JSON/CSV

## Требования

- Windows 10/11 (x64)
- Права администратора (для переключения схем питания)
- Питание от сети (AC) — тест не запускается на батарее
- Минимум 2 схемы питания для сравнения
- 250 МБ свободного места на диске (для истории и сырых сэмплов)

## Быстрый старт

### CLI

```powershell
# Список доступных схем питания
powerbench-cli list

# Быстрый тест (пресет "quick": 30 с прогона, 3 с разогрева, 1 раунд)
powerbench-cli bench --preset quick --schemes "guid1,guid2"

# Подробный тест (пресет "detailed": 60 с, 8 с, 5 повторов — значения по умолчанию)
powerbench-cli bench --preset detailed --schemes "guid1,guid2,guid3"

# Продолжить прерванную сессию
powerbench-cli resume

# Статус контрольной точки
powerbench-cli status

# История сессий
powerbench-cli history list

# Экспорт результата (plan — GUID плана либо all)
powerbench-cli history export all --format csv --out .\exports

# Полный список подкоманд и флагов
powerbench-cli --help
```

### GUI

Запустите `powerbench-app.exe`. Интерфейс ведёт через шаги:
1. Проверка готовности системы (права, питание, схемы, диск)
2. Выбор пресета и схем питания
3. Запуск сессии с live-телеметрией
4. Просмотр результатов и рекомендации
5. Сохранение в историю / экспорт отчёта

## Пресеты

| Пресет | Длительность | Разогрев | Охлаждение | Раунды | Фазы (из 60 с) | Назначение |
|--------|-------------|----------|------------|--------|----------------|------------|
| `quick` | 30 с | 3 с | 3 с | 1 | 8 / 6 / 8 / 8 | Скрининг: отсеять явно слабые схемы |
| `detailed` | 60 с | 8 с | 5 с | 5 | 17 / 12 / 19 / 12 | Полное сравнение (по умолчанию) |

Фазы в порядке «Лёгкая / Частичная / Тяжёлая / Отклик». Длительность делится
на них по правилу: база по 4 с на фазу, остаток — 30 % лёгкой, 20 % частичной,
35 % тяжёлой, остаток (≈15 %) — «Отклику».

`quick` не строит доверительный интервал (один раунд) и не предназначен для
выбора победителя; `detailed` — минимальный пресет, на котором адаптивная
остановка вообще срабатывает.

### Флаги `bench`

| Флаг | Значение | По умолчанию / границы |
|------|----------|------------------------|
| `--preset` | `quick` или `detailed` | `detailed` |
| `--duration` | длительность измеряемой части, с | 16…3600 |
| `--warmup` | разогрев профилем «Отклик», с | от 2 |
| `--cooling` | пауза между прогонами, с | 0…60 |
| `--reps` | число раундов | 1…9 |
| `--threshold` | порог фоновой нагрузки на ядро, % | 0,5…100 (5,0) |
| `--workers` | воркеров пула | логические ядра − 2 |
| `--schemes` | GUID через запятую | интерактивный выбор |
| `--plan` | GUID плана со своими настройками | — |
| `--out` | путь итогового JSON | `%LOCALAPPDATA%\PowerBench\benchmark-result.json` |
| `--allow-dirty-background` | начать при фоне выше порога | выключен |

`resume` берёт план из контрольной точки, поэтому `--schemes` и `--plan` для
него не поддерживаются.

> Конфигурационных файлов у CLI нет: параметры задаются только флагами. Раньше
> в репозитории лежал `bench.example.toml` с ключами и флагом `--config`,
> которых никогда не существовало, — теперь это справочник реальных флагов.

## Архитектура

```
powerbench-core      # Ядро нагрузки GamingCpuV1 (движок, пул, контрольные суммы)
powerbench-metrics   # Статистика: перцентили, стабильность, агрегация
powerbench-recommend # Рекомендации: bootstrap, уровни доказательности, ничьи
powerbench-windows   # Windows API: powercfg, приоритет, сон, мониторинг процессов
powerbench-orchestrator # Сессия: фазы, раунды, чекпоинты, восстановление
powerbench-cli       # Консольный интерфейс
powerbench-app       # Tauri GUI
```

## Детерминизм

- **Seed**: `0xC52A202600000001` — фиксирован в спецификации
- **Хэш конфигурации**: SHA-256 от параметров профилей (зафиксирован в коде)
- **Порядок схем в раунде**: детерминированная ротация против «кто первый» (`cycle = round / n`, чётный — прямой порядок, нечётный — реверс, сдвиг `round mod n`; см. `round_order`)
- **Контрольные суммы**: цепочка FNV-подобных миксов — проверяются при каждом reset

Повторный запуск с тем же планом даёт **идентичные** сигнатуры и контрольные суммы.

## Уровни доказательности рекомендации

| Уровень | Критерий |
|---------|----------|
| `Confirmed` | ≥3 прогона, CV ≤ 2%, перевес ≥ 1%, P(перевес>1%) ≥ 95%, P(лучший) ≥ 90% |
| `Probable` | ≥3 прогона, перевес > 0%, P(перевес>0%) ≥ 80%, P(лучший) ≥ 60% |
| `StabilityTieBreak` | Практическая ничья (≤1%), разрешена по P1/Stability/CV/P0.1 |
| `Preliminary` | <3 прогона или высокая неопределённость |
| `KeepCurrent` | Ничья, выбрана исходная/активная схема |
| `Equivalent` | Схемы статистически неразличимы |

## Структура выходных данных

Результат сессии — JSON (`benchmark-result.json`) с полями:
- `plan_guid`, `identity` (версия, хэш, seed, CPU, таймер)
- `schemes[]` — агрегаты и прогоны по схемам
- `recommendation` — уровень, рекомендованная схема, 3 вероятности, перевес
- `warnings`, `score_weights`, `early_stop_reason`
